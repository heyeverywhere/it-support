# IT Support Bot

Telegram-бот для регистрации и обработки заявок технической поддержки сотрудников учреждения здравоохранения.

Проект предназначен для локального размещения на сервере учреждения с доступом в интернет.

## Возможности

### Для сотрудников

- Создание заявки через пошаговый диалог.
- Указание ФИО.
- Передача номера телефона через Telegram.
- Указание номера кабинета.
- Добавление описания проблемы.
- Выбор степени срочности.
- Просмотр собственных заявок.
- Получение подтверждения о создании заявки.
- Главное меню с кнопками.
- Раздел помощи.
- Возможность отменить создание заявки.

### Для администраторов

Административная часть находится в разработке.

Планируемые возможности:

- Просмотр новых заявок.
- Просмотр данных сотрудника.
- Просмотр номера телефона и кабинета.
- Фильтрация по статусу и срочности.
- Принятие заявки в работу.
- Назначение ответственного специалиста.
- Отправка ответа сотруднику.
- Завершение или отклонение заявки.
- Журнал действий.
- Формирование отчётов.
- Просмотр оценок качества работы.

## Текущий статус

В проекте уже реализованы:

- запуск Telegram-бота;
- команда `/start`;
- главное меню пользователя;
- пошаговое создание заявки;
- FSM-состояния;
- проверка введённых данных;
- передача номера телефона;
- выбор срочности;
- сохранение заявок в SQLite;
- просмотр заявок через `/my_tickets`;
- повторный запуск без потери данных;
- команда `/cancel`.

В разработке:

- регистрация сотрудников;
- панель администратора;
- уведомления администраторам;
- изменение статусов заявок;
- ответы на заявки;
- оценка качества работы;
- отчёты;
- PostgreSQL;
- журналирование действий.

## Установка

### Требования

Перед установкой необходимо установить:

- Python 3.12 или новее;
- Git;
- Telegram-бота, созданного через BotFather.

Для текущего этапа используется SQLite, поэтому отдельная установка базы данных не требуется.

### Клонирование проекта

```bash
git clone https://github.com/USERNAME/it_support_bot.git
cd it_support_bot
```

Замените `USERNAME` на имя пользователя GitHub.

### Создание виртуального окружения

#### Windows CMD

```cmd
py -m venv .venv
.venv\Scripts\activate.bat
```

#### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

#### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Установка зависимостей

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Настройка

Создайте рабочий файл `.env` на основе `.env.example`.

### Windows CMD

```cmd
copy .env.example .env
notepad .env
```

### Linux

```bash
cp .env.example .env
nano .env
```

Пример конфигурации:

```env
BOT_TOKEN=
DATABASE_URL=sqlite+aiosqlite:///./it_support.db
REDIS_URL=redis://localhost:6379/0
ADMIN_IDS=
APP_ENV=development
LOG_LEVEL=INFO
```

### Параметры конфигурации

| Параметр | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `DATABASE_URL` | Строка подключения к базе данных |
| `REDIS_URL` | Адрес Redis |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `APP_ENV` | Режим работы приложения |
| `LOG_LEVEL` | Уровень журналирования |

Пример нескольких администраторов:

```env
ADMIN_IDS=123456789,987654321
```

## Запуск

Активируйте виртуальное окружение и выполните:

```bash
python run.py
```

В Windows CMD:

```cmd
.venv\Scripts\activate.bat
python run.py
```

Для остановки бота нажмите:

```text
Ctrl+C
```

## Доступные команды

| Команда | Назначение |
|---|---|
| `/start` | Запуск бота и отображение главного меню |
| `/new_ticket` | Создание новой заявки |
| `/my_tickets` | Просмотр собственных заявок |
| `/cancel` | Отмена текущей операции |

Основные действия также доступны через кнопки главного меню.

## Безопасность

В проекте не следует хранить секретные данные непосредственно в исходном коде.

Не добавляйте в Git:

- файл `.env`;
- токен Telegram-бота;
- пароли базы данных;
- резервные копии базы данных;
- пользовательские вложения;
- журналы с персональными данными.

Необходимо соблюдать следующие правила:

- использовать `.env` для секретных параметров;
- ограничивать доступ к административной панели;
- проверять Telegram ID администратора;
- не разрешать сотруднику просматривать чужие заявки;
- ограничивать тип и размер загружаемых файлов;
- регулярно создавать резервные копии;
- не передавать в заявках данные пациентов;
- не хранить медицинскую информацию в заявках технической поддержки.
